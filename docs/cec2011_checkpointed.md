# Checkpointed CEC2011: 400000 evaluations

The fresh experiment uses all nine algorithms (no Sep-CMA-ES), all 22 problems,
population 200 and seeds 0–2. Each trial stops solely at exactly 400,000 objective
calls, including initialization and non-finite candidate calls. GA-MPC has no
generation limit. The corrected T3 bounds [0.6,0.9], stabilized CMA-ES, zero PSO
initial velocities, common velocity settings, eta=0.001 and GA fitness reuse are
retained. Total work: 594 trials and 237.6 million evaluations.

```powershell
$env:PYTHONPATH='D:\hppso-git\.deps\cec2011;D:\hppso-git\src'
python -u -m experiments.cec2011_checkpointed --budget 400000 --workers 2 --port 8774
```

Results: experiments/results/cec2011_pop200_fe400k_checkpointed.
Live progress: http://127.0.0.1:8774/. Curves are updated after each problem;
they retain log/symmetric-log y axes and exclude initialization from display.
Final tables and Wilcoxon comparisons use the new budget. Previous 200,000-call
results remain separate. This is a new run, not reconstruction of unsaved old
200,000-call optimizer states.

## What a checkpoint contains

Each trial has a directory in checkpoints/Tn/algorithm/seed_nnn:

* header.json: algorithm identity, seed, dimension, population, fixed schedule
  horizon and scientific-source fingerprint.
* evaluations.bin: ordered 24-byte records containing a 128-bit candidate hash
  and the original float64 objective result. Non-finite results remain in the
  journal and retain the same rejection/counting semantics during replay.
* state.pkl: population/internal optimizer variables from algorithm stack frames,
  current candidate, best solution, logical evaluation count, Python RNG state
  and NumPy RNG state. This includes constructor or partially evaluated generation
  state, so a budget does not need to end at a generation boundary.

Numerical snapshots are saved every 10,000 calls and at the final budget; the
evaluation journal is flushed and synchronized every 1,000 new calls and before
snapshots. Final checkpoints are synchronized before trial completion is saved.
After abrupt power loss, only durable records are guaranteed: the latest
uncommitted calls can need recomputation. Snapshot and plan writes use atomic
replacement and file-lock retries. The plan has a synchronized backup.

Python execution frames are not restored directly from pickle. Recovery reruns
the unchanged optimizer's Python calculations from its seed, feeding stored
fitness results instead of calling the benchmark for previous candidates. This
reconstructs the pending call stack and all numerical state. Candidate hashes
must match every cached evaluation; Python/NumPy RNG state must match the saved
snapshot. Divergence stops recovery rather than silently repeating evaluations.
This approach repeats CPU arithmetic but not objective evaluations from durable
records. It is not an instantaneous direct-memory resume. Native benchmark
functions must be deterministic, as assumed in this CEC2011 experiment.

Do not edit the optimizer code or dependencies between a run and its extension.
The runner rejects incompatible source/software settings. state.pkl is a trusted
local pickle generated by this runner; it should not be replaced by external
pickle files. Raw journals require approximately 5.7 GB for the complete study,
plus numerical snapshots and reports.

## Resume after shutdown

Run the same command. Finished trials are skipped; unfinished trials replay their
durable journals and then perform only the remaining objective evaluations.
If a stale .shard-cec2011.lock remains, verify that no old worker is active before
removing it. Live rows explicitly separate replayed evaluations and new calls.
Recorded elapsed_seconds describes the current invocation, including replay and
checkpoint overhead, rather than cumulative runtime across crashes.

## Extend later without repeating benchmark calls

After the 400,000-call study completes, for example:

```powershell
python -u -m experiments.cec2011_checkpointed --budget 401000 --workers 2 --port 8774
```

Stop the completed runner's HTTP-serving process first to release its port, or
choose a different --port. The same output directory and immutable fingerprint
are retained; budget_history records the extension. Each trial replays its saved
400,000 values, then makes exactly 1,000 new benchmark calls. Earlier final result
records are archived in attempts. The new curves can be reconstructed over the
full retained evaluation history.

Parameter schedules retain their original horizon (400,000) and clamp progress
at one beyond that horizon. Thus extension continues the original trajectory;
it is not identical to a fresh run whose original schedule horizon was 401,000.
Changing a past schedule would invalidate exact continuation.

## Validation

tests/test_optimizer_checkpoint.py verifies all nine algorithms against an
uninterrupted reference: stop at 73 calls, extend to 181, perform only 108 new
calls, obtain byte-identical evaluation journals and identical best solutions,
and reject an altered candidate without invoking its objective. Resuming the
same completed budget makes zero new calls. Tests include mid-generation stops,
intermediate snapshots and RNG checks. tests/test_cec2011_checkpointed.py checks
all 198 native problem/algorithm combinations with partial-population budgets.
